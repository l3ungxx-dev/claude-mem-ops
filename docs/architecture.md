# Architecture

## Problem

claude-mem's observer turns tool calls into "observations". Two failure modes with a local model:

1. **Volume** — every tool call (bash, read, job_output, …) creates an observation. That is a logbook, not memory, and it saturates the local GPU.
2. **Batch limitation** — the `openai-compatible` observer path sends *one tool call per turn* (upstream issue #4967). A busy machine enqueues 600–1000 events/hour while the local model drains fewer than half that; `queueDepth` grows all day.
3. **Detail loss** — if you then reduce volume, the remaining observations are generated by a small local model, which drops numbers, file names and exact assertions. Cloud consolidation cannot recover what was never written.

## Solution: two tiers

### Tier 1 — local, cheap, high-recall index

- `CLAUDE_MEM_SKIP_TOOLS` excludes `bash`, `read`, and management tools; only `write`/`edit`/`send_message`/`team_task_*`/`spawn_*` produce observations.
- The observer model is small (`qwen2.5:3b`): it only needs to write an index (title / short narrative), not a perfect summary.
- **Raw content is not lost**: claude-mem stores every tool call with full input/output in `tool_uses`. Retention is raised to 30 days.

Result: backlog 0–20, GPU ≈ 58 °C / 80 W / 3.7 GB instead of 78 °C / 194 W / 11.5 GB.

### Tier 2 — scheduled cloud consolidation from raw text

`consolidate.py` runs hourly (systemd timer) and for each observation in the window:

1. reads the observation index from `observations`;
2. joins `tool_uses.observation_id` and extracts the **raw** change (write content, edit old/new, message text, …);
3. feeds "index + raw excerpts" to a cloud model (DeepSeek flash or any OpenAI-compatible endpoint);
4. writes `auto/hourly/YYYY-MM-DD/HH.md`; daily/weekly/monthly/yearly rollups reuse the previous layer.

Character budget: 400,000 chars per call. When exceeded, raw excerpts are shortened step by step (600 → 300 → 150 → 80 chars) so **every item keeps its slot**; only in the extreme case is uniform sampling used. Every call records `prompt_tokens` / `completion_tokens` / `cost_cny`, and a daily accumulated cost is kept in the state file with a warning threshold (default ¥10/day).

## Optional: backlog pressure valve

`queue-cloud-router.py` polls `/api/processing-status` every minute. If `queueDepth` ≥ 1000 it switches the observer provider to the cloud via `POST /api/settings` (switch provider first, confirm DeepSeek calls appear in the log, then enable larger batching). When `queueDepth` ≤ 300 or the daily budget is spent it switches back. State: `docs/memory/.monitor/cloud-router.md`.

## Optional: DSH work_state tools

The official `@claude-mem/dsh` integration registers only 5 `mem_*` tools, although the worker's MCP server exposes `work_state_write/read`. `patch-dsh-work-state.py` adds them to the plugin bundle (idempotent, backs up first). Restart `dsh-web` afterwards — the plugin bundle is loaded once per process.
